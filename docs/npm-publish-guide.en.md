# npm Publish Guide (npm-publish-guide.md)

[中文](npm-publish-guide.md)

The release process for `agent-foreman-mcp`. **Publishing requires npm credentials and is performed by a maintainer**; this document records the full procedure and verification steps so any release can be reproduced.

## 0. Prerequisite gates (all required)

Before releasing, every local gate must pass on the target commit:

```bash
npm ci
npm run typecheck && npm run lint && npm test && npm run build
npm run check:stdio      # stdout may carry MCP protocol messages only
npm run pack:check       # verify package contents
```

That commit must also be green in CI across all three platforms (ubuntu / windows / macOS × Node 20/22/24) — `release.yml` enforces that a **successful CI run exists for the same commit** and otherwise refuses to release.

## 1. Version number

The release version comes from `package.json` `version` as the **single source of truth**, and three places must agree:

| Location | How |
|---|---|
| `package.json` | edited by hand |
| `package-lock.json` | refreshed via `npm install --package-lock-only` |
| `src/version.generated.ts` | **never edit by hand** — regenerated by `scripts/sync-version.mjs` during `npm run build` |

## 2. Credentials (choose one)

### Option A: command-line login

```bash
npm login --registry=https://registry.npmjs.org
```

Enter username / password / email plus the one-time code; `~/.npmrc` then holds the `_authToken`.

> If your `~/.npmrc` points at a mirror registry (e.g. npmmirror), `npm login --registry` writes into the npmjs section without conflict. **But publishing must explicitly pass `--registry=https://registry.npmjs.org`** (mirrors are read-only).

### Option B: Granular Access Token

1. https://www.npmjs.com → avatar → **Access Tokens** → **Generate New Token**.
2. Choose **Granular** or **Publish** (publish-only permission is sufficient).
3. Use it without writing to disk:

```bash
export NODE_AUTH_TOKEN=npm_xxxx          # Windows PowerShell: $env:NODE_AUTH_TOKEN="npm_xxxx"
npm publish --registry=https://registry.npmjs.org --access public
```

## 3. Publish

```bash
npm publish --registry=https://registry.npmjs.org --access public
```

## 4. Post-publish verification (record every item)

```bash
# (1) the version is visible on the registry
npm view agent-foreman-mcp version --registry=https://registry.npmjs.org

# (2) launch it with npx from a clean temp dir and smoke-test the protocol (expect 11 tools)
mkdir -p /tmp/npx-smoke && cd /tmp/npx-smoke
npx -y agent-foreman-mcp

# (3) the tarball is downloadable and points at the right place
npm view agent-foreman-mcp dist.tarball --registry=https://registry.npmjs.org
```

## 5. GitHub Release

Pushing a `v<version>` tag triggers `.github/workflows/release.yml`, which:

1. validates that the tag / input version matches `package.json`;
2. runs `npm pack`, asserts on the artifact contents, and runs a strict stdio check in a clean consumer;
3. requires a successful CI run for that commit;
4. composes the body with `scripts/release-body.mjs` — **the body comes from `docs/release-v<version>.md` and `.en.md`, and a missing document fails the workflow** (so it can never ship an empty body with only a Full Changelog);
5. creates the Release with `agent-foreman-mcp-<version>.tgz` attached.

> **First release (1.0.0) note**: the repository has no earlier tag, so `git describe` finds no previous version and the Full Changelog falls back to a `commits/v1.0.0` link. That is expected behaviour, not a defect; from v1.0.1 onward it returns to the `compare/v1.0.0...v1.0.1` form.

## 6. Troubleshooting

| Problem | What to do |
|---|---|
| `ENEEDAUTH` / `401` | Token not in effect: `npm whoami --registry=https://registry.npmjs.org` should return your username |
| Want a mirror for speed but publish to npmjs | Mirrors are read-only; publishing must use `--registry=https://registry.npmjs.org` |
| `release.yml` complains about a missing release note | Write `docs/release-v<version>.md` and `.en.md` before pushing the tag |
| `release.yml` says "no successful CI for the target commit" | Wait for that commit's CI to go green, or fix CI first |
| The package name is taken | This name is confirmed available; if that ever changes, rename and update `package.json` / README / docs / CI together |

## 7. The old package is not published

The historical `tianshu-mcp` is **a separate, independent project**. This repository **does not publish, deprecate or otherwise touch** its npm package, which continues to be maintained independently. Releases from this repository target `agent-foreman-mcp` only.
